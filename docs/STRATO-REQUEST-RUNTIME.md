# Permanent registration and staff entry

14 November 2026. `api/requests.php` is a thin public entry for `/api/registration`, `/api/registration/token` and `/intern/anmeldungen`. Both plain export routing and versioned release routing include these paths. The original unconditional `api/registration.php` remains an inactive legacy entry. There is no Node runtime on STRATO.

The new entry reads a root `.pk-registration-location.json` containing path metadata only. Dotfile routing denies HTTP access. Its runtime source, domain classes, policy, database credentials, keys and activation settings remain outside the public root. Missing, oversized, invalid or public-root locators/configuration fail closed with a generic no-store/noindex 503; no submitted body or database access is needed. A direct request to the thin entry is not an alternate API route.

`node hosting/strato/provision-request-runtime.mjs` uses the existing pinned SFTP connection, shared release lock and a one-use dual-authenticated helper. It installs a complete hash-verified, versioned private bundle with a **disabled** runtime descriptor and **false** intake acceptance gates. It references the already provisioned private database/staff configuration. It neither migrates a database nor creates an account, changes existing activation settings or enables genuine intake. It refuses to overwrite differing existing source/configuration/locators, including an activated descriptor. Helpers must be removed and their 404 verified. Run only after publishing the new permanent routes; local hosting credentials and verified path metadata are already ignored.

Activation remains a separate operation: runtime descriptor, staff configuration, intake policy/version/hash/host review/real-data settings and database pause state are independent. All need the accepted production choices; setting a public build flag alone cannot enable collection. `PUBLIC_REGISTRATION_ENABLED` defaults false. A true value requires the STRATO target and a versioned policy explicitly marked approved/publicIntakeEnabled; otherwise the build fails. Protected publishing reads the still-unset `STRATO_REGISTRATION_ENABLED` repository variable. No flag or policy was enabled. When accepted, the same gate exposes the form and requestable schedule links to `/anmeldung#formular`; no SpielerPlus URL or further feature implementation is required. Do not replace an accepted runtime pointer merely to upgrade source; review the private state and use a controlled rollback-aware change.

The current source uses the existing published training retrieval boundary to list only future, open, non-demo sessions at active venues, excluding exhausted capacity. Labels use Europe/Berlin time. Build-time choices are hints: the PHP endpoint rechecks the current published session. Package requests do not require an invented session; SpielerPlus stays separate.

Registration pages use native navigation, while the other pages retain Astro transitions. Uncertain writes keep their original body/token in page memory, freeze editing and block ordinary navigation; native back/reload prompts can retain that state. No sensitive values enter history or browser storage. A cancelled back/reload followed by retry is covered by the integrated local browser test.
